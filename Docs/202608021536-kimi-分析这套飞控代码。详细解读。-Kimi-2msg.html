这是一套基于 ESP32/ESP32-S3 的微型四旋翼飞控代码，项目名为「耀坤无人机」（YaoKun Drone）。代码采用 Arduino + 模块化拆分 架构，通过 WiFi AP + WebSocket 提供无线遥控与调参界面。
以下从架构设计、核心算法、安全机制、通信协议、硬件抽象五个维度进行详细解读。

一、项目架构与文件组织

代码采用 "头文件声明 + .ino 实现" 的混合模块化方案，在 Arduino 单项目限制下做了合理的职责拆分：
表格
文件职责
YaoKun_Drone21.ino主入口：setup()/loop()、控制主循环 controlStep()、WiFi/Web 服务器
config.h硬件抽象层（HAL）：多板型条件编译、引脚定义、全部系统常量
drone_types.h项目"公共头文件"：数据结构、枚举、跨模块 extern 声明、工具函数
drone_pid.h通用 PID 控制器类（头文件内联实现）
control.inoPID 对象实例化、参数热更新、增益应用
drone_imu.hIMU 驱动接口与姿态解算类声明（Madgwick/Mahony/互补滤波）
hardware.ino底层硬件实现：LED、蜂鸣器、电机 PWM、IMU 读写
failsafe.ino安全核心：解锁状态机、紧急停止、故障保护
rc.ino通信核心：WebSocket 命令解析、遥控指令存储、PID/配置热修改
telemetry.ino遥测数据打包（JSON via WebSocket）
storage.inoNVS 非易失性存储：参数掉电保存
drone_web_ui.h完整的 Web 遥控界面（单 HTML 文件，内嵌 CSS/JS）
drone_led.h / drone_buzzer.hLED/蜂鸣器模块头文件与接口定义
设计亮点：在 Arduino 不支持传统 .c/.cpp 分离编译的约束下，通过 extern 声明 + 单一 .ino 实现文件的方式，实现了接近专业飞控的模块化结构。

二、硬件抽象层（config.h）

2.1 多板型支持

通过条件编译支持多种 PCB：
  • PCB_YaoKun_LCKFB_ESP32S3：立创 ESP32-S3 R8N8 全功能版（带光流/激光预留插座）
  • PCB_YaoKun_S3mini 系列：Supermini 精简版（引脚紧张，无光流）
  • 预留了 ESP32Dev、ESP32C3、ESP32S3-CAM 等未来板型

2.2 关键硬件参数

  • PWM：20kHz 10-bit（0~1023），使用 ESP32 LEDC 硬件通道
    • 通道 0~3：电机（与引脚绑定）
    • 通道 4~5：红/绿 LED 呼吸灯
  • 控制频率：500Hz（周期 2ms）
  • IMU 支持：自动检测 MPU6050（I2C）或 MPU6500（SPI）
  • IMU 轴映射：通过 kImuSwapXY、kImuFlipX/Y/Z 宏适配不同模块安装方向

三、核心控制算法详解

3.1 控制架构：串级 PID（角度环 + 角速率环）

plain
遥控输入 → 角度环 PID → 期望角速度 → 角速率环 PID → 电机扭矩 → 混控 → PWM
具体实现（controlStep() 中）：
cpp
// 外环：角度误差 → 期望角速度
float roll_rate_sp  = g_roll_angle_pid.update(roll_sp_deg - g_roll_deg, dt);
float pitch_rate_sp = g_pitch_angle_pid.update(pitch_sp_deg - g_pitch_deg, dt);

// 内环：角速度误差 → 归一化扭矩（-0.5~0.5）
float roll_torque  = g_roll_rate_pid.update(roll_rate_sp - s.gx_dps, dt) * torque_scale;
float pitch_torque = g_pitch_rate_pid.update(pitch_rate_sp - s.gy_dps, dt) * torque_scale;
float yaw_torque   = g_yaw_rate_pid.update(yaw_rate_sp_dps - s.gz_dps, dt) * torque_scale;
PID 实现特点（drone_pid.h）：
  • 标准位置式 PID
  • 积分抗饱和：当输出触及限幅时，积分项乘以 0.99 缓慢衰减
  • 输出限幅独立设置：角度环 ±250，角速率环 ±0.5，偏航 ±0.3

3.2 姿态解算：三滤波器自适应切换

支持三种算法，通过 Web 界面实时切换（仅在上锁时允许）：
表格
滤波器特点适用场景
Madgwick梯度下降法，自适应 beta（根据加速度信任度 0.02~0.14 动态调整）通用，对噪声有一定鲁棒性
Mahony比例-积分修正 DCM 法，支持加速度信任度和自旋限制默认方案，计算量小，效果稳定
互补滤波简单加权融合（陀螺仪 98% + 加速度计 2%）最轻量，适合资源极度受限场景
切换连续性保障：
cpp
// 切换时，从旧滤波器读取当前姿态，写入新滤波器，避免跳变
if (imu_mode != active_mode) {
    g_ahrs_madgwick.setEulerDeg(r0,p0,y0);
    g_ahrs_mahony.reset(); g_ahrs_mahony.setEulerDeg(r0,p0,y0);
    // ...
}

3.3 X 型混控逻辑

机头位于 M4(左前) 和 M1(右前) 之间，标准 X 配置：
cpp
m0(左前) = throttle + roll  + pitch - yaw;
m1(右前) = throttle - roll  + pitch + yaw;
m2(右后) = throttle - roll  - pitch - yaw;
m3(左后) = throttle + roll  - pitch + yaw;

3.4 扭矩缩放（低油门操控性补偿）

cpp
float torque_scale = clampf(torque_scale_min + throttle * torque_scale_slope, 0, 1);
  • 解决低油门时 PID 输出相对油门占比过大的问题
  • 默认 min=0.20, slope=2.0，即油门 0% 时扭矩系数 0.2，油门 40% 时达到 1.0

四、安全机制与故障保护（failsafe.ino）

4.1 多层安全架构

plain
1. 硬件初始化检查 → 电机/IMU 故障则禁止启动
2. 解锁条件检查 → 油门低位、摇杆回中、姿态水平（<45°）
3. 解锁保持机制 → ARM 开关需保持 800ms 才正式解锁
4. 运行中实时监控 → 倾斜/超时/IMU失效/dt超限 → 强制上锁
5. 紧急停止（Kill）→ 任意时刻收到 'K' 指令或 WebSocket 断开 → 立即停转

4.2 故障保护触发源（FailSafeReason）

表格
代码触发条件行为
FS_CMD_TIMEOUT遥控指令超过 timeout（默认 300ms）未更新上锁 + 蜂鸣器急促报警
FS_WS_DISCONNECTWebSocket 客户端断开上锁
FS_IMU_FAILIMU 读取失败或姿态解算出 NaN/Inf上锁 + 报警
FS_TILT_LIMIT横滚/俯仰超过 tilt_disarm_deg（默认 80°）上锁 + 报警
FS_DT_LIMIT控制循环间隔超过 20ms（500Hz 失速）上锁 + 报警
FS_KILL收到紧急停止指令上锁 + 专用音效
FS_MOTOR_FAILLEDC 初始化失败永久禁止解锁

4.3 解锁状态机（updateArmingState）

cpp
if (!g_armed) {
    // 检查 canArm()：油门低、摇杆中、姿态平
    if (rc.arm_request && canArm(rc)) {
        if (保持时间 >= 800ms) {
            g_armed = true;  // 正式解锁
            resetAllPid();   // 清零历史积分
            buzzerPlay(BUZ_LONG_BEEP);
        } else {
            buzzerPlay(BUZ_QUICK_TICK); // 解锁等待滴答声
            g_led_mode = LED_ARMING;    // 红绿灯慢闪
        }
    }
} else {
    if (!rc.arm_request) disarmNow(FS_MANUAL); // 关 ARM 立即上锁
}

  • HTTP：提供静态网页（kIndexHtml 存储在 PROGMEM 中）

5.4 Web 界面特性

  • 虚拟摇杆：支持触摸/鼠标，左摇杆（油门不回中，偏航回中），右摇杆（回中）
  • 姿态仪表：Canvas 绘制 ADI（民航姿态仪风格），蓝天绿地，地平线反向倾斜
  • 12 色主题：从浅色系到深色系（暗黑、海棠、朱红、藕荷、湖蓝、晴蓝、藏青、葱绿、甘青、翡翠、松花）
  • 全屏支持：移动端沉浸式体验
  • 设置页面：PID 调参、限制参数、滤波器切换、蜂鸣器设置
  • 电机测试：独立控制单个电机，带油门/时长限制

六、硬件驱动层（hardware.ino）

6.1 电机驱动

  • 使用 ESP32 ledcAttachChannel 将电机绑定到通道 0~3
  • motorWriteNorm() 将 0.0~1.0 浮点油门映射到 0~1023 duty
  • 电机测试状态受互斥锁 g_motorTestMux 保护

6.2 IMU 驱动

统一接口设计（ImuDriver 类）：
cpp
bool begin();      // 自动探测：先尝试 I2C(MPU6050)，失败则尝试 SPI(MPU6500)
bool read(ImuSample *out);  // 统一输出 g 和 dps
void calibrateGyro();       // 上电自动零偏校准
数据后处理（适配不同安装方向）：
cpp
if (kImuSwapXY) { swap(ax, ay); swap(gx, gy); gx=-gx; gy=-gy; }
if (kImuFlipX)  { ax=-ax; gx=-gx; }
// ...

6.3 LED 与蜂鸣器

  • 红绿 LED：LEDC PWM 呼吸/闪烁，模式由 g_led_mode 全局状态控制
  • 蓝色 LED：独立 GPIO 逻辑，表示连接状态（慢闪=待机，常亮=WebSocket 连接，快闪=飞行中）
  • 蜂鸣器：非阻塞状态机，支持 14 种音效模式，包括循环报警和电压分级告警

七、参数存储（storage.ino）

使用 ESP32 Preferences（基于 NVS）：
  • 存储内容：PID 三组 9 个参数、运行限制 7 项、水平校准偏置 3 轴、滤波器模式、蜂鸣器设置
  • 掉电保持：saveTunings() 在修改后调用，loadTunings() 在 setup() 时调用
  • 热更新：Web 修改 PID 时只改内存并置 g_tunings_dirty 标志，控制循环在 applyTuningsIfDirty() 中安全切换，避免临界区问题

八、代码质量评估

8.1 优点

  1. 模块化清晰：在 Arduino 限制下做到了较好的职责分离
  2. 线程安全：关键全局变量（RC 指令、配置、电机测试状态）均使用 portMUX_TYPE 临界区保护
  3. 安全设计完善：多层故障保护、解锁条件严格、积分抗饱和、输出限幅
  4. 硬件兼容性好：条件编译支持多板型，IMU 自动探测
  5. Web 交互完整：无需额外 App，浏览器即遥控器和调参助手
  6. 注释详尽：关键算法（PID、混控、IMU 映射）都有中文注释，适合教学

8.2 可改进点

  1. 浮点精度：部分比较使用 == 判断浮点（如 PID 输出限幅抗饱和），理论上应使用容差
  2. 内存管理：WebSocket 接收缓冲区固定 192 字节，超长指令可能截断；JSON 遥测使用 snprintf 栈缓冲区，存在潜在溢出风险（虽然当前尺寸可控）
  3. 错误恢复：IMU 初始化失败进入 while(true) 死循环，无看门狗或降级策略
  4. 调度抖动：loop() 使用 delayMicroseconds(50) 忙等待，可改用 FreeRTOS 任务或硬件定时器进一步降低抖动
  5. 无传感器融合扩展：当前预留了光流/激光引脚，但代码中未实现位置/速度环

九、总结

这是一套教育级/入门级的开源飞控，代码量精简但功能完整，涵盖了四旋翼飞行的核心要素：
  • ✅ 500Hz 串级 PID 控制
  • ✅ 三种姿态解算算法（Madgwick/Mahony/互补）
  • ✅ 完整的故障保护与解锁逻辑
  • ✅ 基于 WebSocket 的无线遥控与实时调参
  • ✅ 多硬件板型支持
其代码组织方式和详尽的注释使其非常适合作为 ESP32 飞控的学习模板 或 小型四轴的二次开发基础。如果后续加入光流/激光测距模块，可以在此基础上扩展为具有定高/悬停功能的进阶版本。
